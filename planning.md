### Tool 1: search_listings

**What it does:**
<!-- Describe what this tool does in 1–2 sentences -->
Searches the mock secondhand listings dataset for items that match the user’s requested description, optional size, and maximum price. It returns matching listings sorted by relevance.

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
description (str): The item the user is looking for, such as "vintage graphic tee" or "black jacket".
size (str): The requested clothing size, such as "M" or "L". This can be None if the user does not specify a size.
max_price (float): The highest price the user is willing to pay.

**What it returns:**
<!-- Describe the return value — what fields does a result contain? -->
A list of listing dictionaries. Each result may include:

id
title
description
category
style_tags
size
condition
price
colors
brand
platform

**What happens if it fails or returns nothing:**
<!-- What should the agent do if no listings match? -->
If no listings match, the tool returns an empty list. The agent should stop the workflow early and tell the user to try a broader description, higher budget, or different size.

---

### Tool 2: suggest_outfit

**What it does:**
<!-- Describe what this tool does in 1–2 sentences -->
Suggests a complete outfit using the selected listing and the user’s wardrobe. It explains how the new item can be styled with pieces the user already owns.

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
new_item (dict): The listing selected from search_listings, usually the top result.
wardrobe (dict): The user’s wardrobe data containing clothing items with fields like id, name, category, colors, style_tags, and notes.

**What it returns:**
<!-- Describe the return value -->
A string containing one or more outfit suggestions. The suggestion should mention the selected item and specific wardrobe pieces when available.

**What happens if it fails or returns nothing:**
<!-- What should the agent do if the wardrobe is empty or no outfit can be suggested? -->
If the wardrobe is empty or minimal, the tool should still return a useful general styling suggestion instead of crashing. For example, it can suggest common outfit pairings based on the item’s category, colors, and style tags.
---

### Tool 3: create_fit_card

**What it does:**
<!-- Describe what this tool does in 1–2 sentences -->
Creates a short, shareable caption for the completed outfit. The fit card should sound casual and social-media friendly.

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
outfit (str): The outfit suggestion generated by suggest_outfit.
new_item (dict): The selected listing from search_listings.

**What it returns:**
<!-- Describe the return value -->
A short caption-style string that references the selected item and the outfit vibe.

**What happens if it fails or returns nothing:**
<!-- What should the agent do if the outfit data is incomplete? -->
If the outfit input is missing or empty, the tool should return a clear error message string like: "I need an outfit suggestion before I can create a fit card."

## Planning Loop

**How does your agent decide which tool to call next?**
<!-- Describe the logic your planning loop uses. What does it look at? What conditions change its behavior? How does it know when it's done? -->
Call search_listings(description, size, max_price).
Check the search results.
If the results list is empty, save an error message in the session and return early.
Do not call suggest_outfit or create_fit_card if no listing was found.
If results exist, select the top listing as selected_item.
Store selected_item in the session.
Call suggest_outfit(selected_item, wardrobe).
Store the returned outfit suggestion in the session as outfit_suggestion.
If the outfit suggestion is missing or empty, save an error message and stop before creating a fit card.
Call create_fit_card(outfit_suggestion, selected_item).
Store the returned fit card in the session as fit_card.
Return the full session so the app can display the selected listing, outfit suggestion, fit card, or error message.

## State Management

**How does information from one tool get passed to the next?**
<!-- Describe how your agent stores and accesses state within a session. What data is tracked? How is it passed between tool calls? -->
The agent uses a session dictionary to pass information between tools during one interaction.

The session tracks:

query: the original user request
description: the parsed item description
size: the requested size
max_price: the user’s budget
search_results: the list returned by search_listings
selected_item: the top listing chosen from search results
wardrobe: the wardrobe data used for styling
outfit_suggestion: the string returned by suggest_outfit
fit_card: the string returned by create_fit_card
error: an error message if the workflow stops early

The selected_item returned by search_listings is passed directly into suggest_outfit. The outfit_suggestion returned by suggest_outfit is passed directly into create_fit_card.
